# 25 - V4 实施计划

> 规划定稿：2026-09-29 ｜ 前置状态：V3 全线收官（[docs/24](24_V3终态交付总结.md)）
> 本计划遵循项目既定哲学：分阶段实现、每阶段四矩阵编译 + 冒烟可验证、显式导出不进热路径（PRD 14）、克制配置面

---

## 1. 版本定位与主题

V1~V3 完成了能力建设：事件监控 → MetaCall 归因 → QSS → 统计/诊断 → IPC 配置 → 调用栈/风暴抑制 → 冻结看门狗 → SQLite/HTML 数据消费。终态基准（docs/22 §8）确认监控器不成为新的卡顿来源。

**V4 主题：工程化与规模化**——解决三件 V3 留下的事：

1. **防腐化**：四矩阵 + 冒烟 + 基准全靠手动跑，无基线漂移检测——最大的质量风险不在代码，在验证流程本身；
2. **可分发**：add_subdirectory 单模型 + config 目录连带公共 + 无 install 支撑，离"给别人直接用"差最后一层；
3. **规模化场景**：多进程（多实例应用）跨进程数据汇聚是 C3 搁置项转正的唯一功能级候选。

## 2. 阶段总览与优先级

| 阶段 | 内容 | 优先级 | 定性 | 依赖 |
|---|---|---|---|---|
| A | 回归基建（一键本地回归 + CI 模板） | **P0** | 工程守护，量小收益最大 | 无 |
| B | 性能与配置微调（抑制窗口配置化 + 栈采集时机可配置） | **P1** | 有数据支撑的收口 | 无 |
| C | API 与分发收尾（config 藏匿 + install 模型） | **P1** | 为分发铺路 | 无 |
| D | 多进程聚合（上行链路 + 中心收集器） | **P2** | 旗舰可选，量大 | A（回归基建先行） |
| E | Linux 验证 | 条件触发 | 环境依赖，不阻塞 | 环境具备 |

推进建议：A → B/C（可并行）→ D（A~C 落地后按需启动）→ E（条件触发）。

## 3. Phase A：回归基建（P0）

### A1 本地一键回归脚本

- **目标**：把当前手动四矩阵流程固化为一条命令，且能检测基准漂移。
- **任务**：
  1. `scripts/regression/qt-matrix.json`：四矩阵清单（构建目录 / Qt bin / 工具链 bin / generator），路径以本机为准（F:\IDE.2\... 双 Qt 根）；
  2. `scripts/run_regression.ps1`：逐矩阵 `cmake --build`（全目标）→ `TestEventWatcher` 冒烟 → benchmark 快速档（`off` + `slow` 两模式）→ 汇总为 Markdown 结果表（矩阵 × 步骤 × PASS/FAIL + 基准数字）；
  3. `scripts/regression/baselines-v3.json`：固化 docs/22 §8 终态数据（①~③全部场景 × 四矩阵）；对比容差 **±25%**（单次运行噪声实测 <10%，留余量），超限项标 `DRIFT` 并 FAIL；
  4. `--full` 开关：benchmark 跑全 5 模式（含 metacall / alert-first，约 +60s/矩阵）。
- **验收**：一条命令产出四矩阵 PASS/FAIL 表；人为将某告警路径放大后 DRIFT 可检出。
- **风险**：低。基准噪声靠同机对照法（既有 harness）已控制。

### A2 CI 工作流模板

- **目标**：CI 兜底编译 + 冒烟（本地脚本为主，CI 为辅——基准在共享 runner 上噪声大，不进 CI 门禁）。
- **任务**：
  1. `.github/workflows/regression.yml`：windows-latest + aqtinstall 拉取 Qt 5.15.2 / 6.5.3（msvc2019_64 + mingw 对应套件），四 job 矩阵 = configure + build + 冒烟；
  2. spdlog 按 docs/23 现有集成方式在工作流中复原；
  3. 明确注释：CI 不跑基准（runner 噪声），只保证可编译可冒烟。
- **验收**：模板在 GitHub 上一次绿跑（若暂无远端仓库则交付模板 + 本地验证说明）。
- **风险**：中低——aqt 套件名随 Qt 版本变化、MinGW 工具链需匹配；模板标注"以 aqt 官方 list 为准"。

## 4. Phase B：性能与配置微调（P1）

### B1 抑制窗口配置化（A2 遗留收口）

- **任务**：
  1. AlarmSuppressor 窗口从编译期常量 1000ms 改为 `AlarmSuppressWindowMs`（WatchConfig 字段，默认 1000 保持现状）；
  2. 三通道接入：环境变量 `QT_EVENT_WATCHER_ALARM_SUPPRESS_WINDOW_MS`（纯十进制）+ INI + IPC setter；evaluate(key, nowMs) 调用点实时读 config（同 WatchFreeze 开关 run() 每轮查询模式）。
- **验收**：冒烟加合成时钟断言（窗口 100ms 时第二条进汇总）；默认值下行为与 V3 逐字节一致。
- **风险**：低。不改变默认语义。

### B2 栈采集时机可配置（D1 候选优化落地）

- **背景**：终态基准确认完整告警 3.4× 主增量 = 栈采集 + 格式化，且当前栈采集在抑制判定**之前**（EventWatcher.cpp 告警路径）——被抑制事件也付采集成本（风暴抑制路径 15.6~18.6µs 的大头）。
- **任务**：
  1. WatchConfig 新增 `StackCaptureMode`（bit 段或独立字段）：`0` = 阈值命中即采（**现状，默认**，记录全量含 frames）/ `1` = 仅窗口首条采（抑制后续免采，其记录**无 frames 字段**）/ `2` = 关闭；
  2. 告警路径重排：先 evaluate 抑制判定，再按 mode 决定是否 capture（mode=0 保持现有先采后判，兼容默认）；
  3. 三通道热更新 + DataExporter frames 缺失容错确认（现有 parseFrames 已跳过坏帧，验证 mode=1 导出无异常）。
- **验收**：benchmark 三档实测（重点：mode=1 下风暴抑制路径 15.6~18.6µs → 预期 ≤5µs）入 docs/22 §9；默认档数字与 V3 基线一致。
- **风险**：中低——语义权衡必须文档化：mode=1 时 WatchRecordStore 记录失去 frames（违背"全量记录"语义，换取风暴期 CPU 降幅 ~10µs/条）；默认 0 不动，由使用者按场景选择。
- **明确不做**：告警日志格式化与 sink 落盘不做进一步压缩——仅阈值命中事件付费，已是 PRD 14 模型。

## 5. Phase C：API 与分发收尾（P1）

### C1 config 目录彻底藏匿

- **背景**：CusApplication.h 按值持有 `WatchConfig m_config` 导致 `#include "WatchConfig.h"` 必须公共（D2 审计结论）。
- **任务**：
  1. CusApplication 改 `std::unique_ptr<WatchConfig>`（析构已 out-of-line，满足不完整类型规则——B1 已踩平此路）；头文件前置声明，`#include "WatchConfig.h"` 移入 .cpp；
  2. 公共接口审查：config() 访问器语义保持（内部指针化，外部仍拿引用/快照）；
  3. src/CMakeLists.txt：config 目录 PUBLIC → PRIVATE，公共面收窄为 application / logging / qss / include 四目录；
  4. tests / benchmark / basic_demo 白盒清单同步补 config。
- **验收**：四矩阵全量重建 + 冒烟全绿；公共头集合审计（仅 CusApplication.h / WatchLogger.h / QssStyleWatcher.h / WatchEventInfo.h 可被 consumer include）。
- **风险**：低——纯存储形态改造，公共接口不变；WatchConfig 纯值语义（原子替换通道不受影响）。

### C2 install 模型与 CMake package

- **任务**：
  1. `cmake --install` 支持：4 公共头 + QtEventWatcherCore 静态库 + 导出目标；
  2. `QtEventWatcherConfig.cmake`（`CMakePackageConfigHelpers` 生成）——消费方 `find_package(QtEventWatcher)` 可用；
  3. 最小消费工程 `examples/consume-test`（单 main.cpp：CusApplication 接入 + WatchLogger 打点）作为双模型验收载体（add_subdirectory 与 find_package 各跑一遍）。
- **验收**：consume-test 两模型四矩阵编译通过（install 前缀隔离目录验证干净卸载）。
- **风险**：中低——静态库传递依赖（Qt::Network/Sql、spdlog）需在 Config 里正确 `find_dependency`；spdlog 集成方式（docs/23）决定是否需要额外 find 模块。
- **产出意义**：分发形态完备——此后可打 zip 包给其他工程直接 `find_package` 接入（对齐个人打包分发工作流）。

## 6. Phase D：多进程聚合（P2，旗舰可选）

**场景**：多实例桌面应用（多进程）+ 边缘多设备网关——各进程监控数据汇聚到中心控制台统一观测。

### D1 上行链路（监控端）

- **协议**：复用 QLocalSocket + JSON 行协议（与 IPC 配置同构反向），新增 `op=record.push`（批量：单行 ≤8KB 携带 ≤N 条记录摘要，字段对齐 WatchRecordStore records 的 key=value 结构 + raw 兜底）。
- **UplinkClient**（src/ipc/，非 QObject 组合式）：有界队列（1024 条）+ 专线上下文；**背压铁律**——队列满丢弃并递增 droppedCount（随下次 push 附带），**绝不阻塞监控/告警线程**；断线静默重连（指数退避上限 5s），失败计数可查。
- **配置**：`QT_EVENT_WATCHER_UPLINK_NAME`（默认关闭，设置即启用）+ INI + IPC 三通道；上行开关与过滤（只推 WARN+ / 全量）复用现有级别路由。
- **风险**：中——上行在告警路径之外（记录侧异步排空），但必须基准复测证明开启上行后 ② 正常路径增量不变（预期 +<50ns 入队）。

### D2 中心收集器（examples/aggregator 控制台）

- QLocalServer 多连接管理（连接名注册表：pid → 会话）+ 聚合环形存储（复用 WatchRecordStore 语义，按进程分组，上限 4×4096）；
- 输出三件套复用 DataExporter：CSV / JSON / SQLite（records 表加 host_pid 列）；
- 实时模式：控制台 tail（按进程过滤 / 全局告警流）。

### D3 聚合 HTML 报告

- HtmlReporter 扩展"多进程段"：按 host_pid 分组的诊断结论 + 跨进程告警 TOP（聚合口径 = 各进程四规则结果合并再排序）。

### 验收

- 端到端：2 个 basic_demo 实例（不同 pid）+ aggregator，冒烟断言聚合 counts / 按 pid 分组 / 断线重连后数据续传 / 队列满丢弃计数上报；
- 四矩阵编译 + 冒烟全绿（aggregator 仅为 console 目标，不入 GUI 矩阵）。

## 7. Phase E：Linux 验证（条件触发，不阻塞）

环境具备后单独立项，清单预置：

1. GCC ≥9 / Clang 双编译器 × Qt 5.15.2 / 6.5.3 四组合编译；
2. StackCapture `#else` 空实现行为确认（记录无 frames，导出容错）；
3. K32*/psapi 等 Windows 门控段在非 Windows 分支的编译排除验证；
4. 看门狗心跳 / 稳定时钟语义在 Linux 调度下的阈值裕度复核；
5. 文档：docs/23 增补 Linux 章节与环境差异记录。

## 8. 依赖关系与推进顺序

```
A（回归基建）──→ B（微调）──→ D（多进程聚合，按需）
      │              │
      │              └── B2 基准复测依赖 A1 基线文件
      └──→ C（API 收尾，可与 B 并行）──→ 分发 zip
E（Linux）＝条件触发，独立
```

- A 先行：B2 / D1 的基准复测都依赖 A1 的基线与一键回归能力；
- B、C 无相互依赖可并行；
- D 建议在 A~C 之后启动（上行链路的回归验证依赖 A1；分发包形态依赖 C2）。

## 9. 风险清单

| 风险 | 阶段 | 缓解 |
|---|---|---|
| 基准漂移误报（机器状态波动） | A1 | 容差 ±25% + 同机对照法 + DRIFT 仅提示不阻断（--strict 才阻断） |
| aqt 套件名 / runner 环境漂移 | A2 | 模板注释标注官方 list 查询法；CI 不做门禁 |
| mode=1 语义争议（记录失 frames） | B2 | 默认 0 不变；权衡文档化；实测数据入 docs/22 §9 供决策 |
| find_dependency 链（spdlog/Qt Sql/Network） | C2 | consume-test 双模型验收前置；Config 写失败即报错不静默 |
| 上行链路反压泄漏进热路径 | D1 | 有界队列 + 非阻塞 tryPush；基准复测 ② 增量 ≤+50ns 为验收线 |
| 聚合存储内存膨胀 | D2 | 按进程 × 4096 环形 + 总上限裁剪（沿用既有环形纪律） |

## 10. 成功标准

对齐项目总纲（docs/21 §8）之上，V4 特有：

1. **一键回归**：新克隆环境一条命令完成四矩阵验证，基线漂移可检出；
2. **默认零回归**：B 阶段所有改动默认档下 V3 基线数字不劣化（docs/22 §9 复测确认）；
3. **分发完备**：consume-test 以 find_package 模型接入成功，公共头集合 = 4 个；
4. **多进程可观测**（D 启动则）：双进程端到端聚合，监控端热路径增量 ≤+50ns；
5. 每阶段交付即更新 docs/21 §9 实施记录与 docs/24 式总结。
