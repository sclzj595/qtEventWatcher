# Qt 卡顿排查辅助器 PRD 23：集成与适配说明

> 交付物"spdlog 集成说明 / Qt 版本兼容说明 / MetaCall ABI 适配说明"三合一归并篇。
> 各主题的 PRD 规范源头：spdlog → PRD 12；版本兼容 → PRD 02/06；MetaCall ABI → PRD 06。
> 接入步骤见 [README.md](../README.md)。

## 1. spdlog 集成说明

### 1.1 引入方式

spdlog（1.17.0）以**源码子构建**随工程分发，位于 `third_party/spdlog-1.x`，经 [cmake/Dependencies.cmake](../cmake/Dependencies.cmake) 接入：

```cmake
include_guard(GLOBAL)
if (NOT TARGET spdlog::spdlog)
    set(SPDLOG_BUILD_EXAMPLE OFF CACHE BOOL "" FORCE)   # 三项全关：仅当库用
    set(SPDLOG_BUILD_TESTS OFF CACHE BOOL "" FORCE)
    set(SPDLOG_BUILD_BENCH OFF CACHE BOOL "" FORCE)
    add_subdirectory(third_party/spdlog-1.x ... EXCLUDE_FROM_ALL)
endif ()
```

- `include_guard` + `if (NOT TARGET)` 双幂等：宿主工程已有 spdlog 时直接复用，不重复构建。
- `EXCLUDE_FROM_ALL`：spdlog 目标不进入宿主的默认构建产物（install/export 干净）。
- Core 对 `spdlog::spdlog` 为 **PUBLIC** 链接（[src/CMakeLists.txt](../src/CMakeLists.txt)）：宿主链接 `QtEventWatcherCore` 即获得 spdlog 头，无需自行 find_package。

### 1.2 日志门控与安全

- 全部工具日志经 `QEW_LOG_*` 宏（[WatchLogMacros.h](../src/logging/WatchLogMacros.h)）输出，**不使用 qDebug**（PRD 12 §1）。宏内先取 logger，`WatchLogger` 未初始化时为空 → **自动静默**，监控链可脱离日志独立运行。
- `WatchLogger::initialize(dir, name, level)` 失败仅记录错误消息，不抛出、不崩溃（PRD 12 §4 / PRD 14 §4：磁盘不可写不得导致主线程崩溃）。
- 热路径纪律（PRD 14 §1）：正常事件不产生日志；notify 内不做文件 IO、不做字符串格式化——仅在命中阈值告警后才格式化输出。这是 [性能基准报告](22_性能基准报告.md) 中"告警路径才付费"的根源。

### 1.3 Sink 架构（WatchLogger 挂载）

| Sink | 用途 | 关键参数 |
|---|---|---|
| 控制台 | 开发期实时观察 | 跟随日志级别 |
| rotating file | 落盘归档 | `./logs` 自动创建，`flush_on(warn)`——告警即落盘，崩溃前证据不丢 |
| WatchLogCapture | UI 环形快照 | 最近 32 条，Demo 日志页 |
| WatchRecordStore | 结构化记录环形 | 最近 4096 条，CSV/JSON 全量导出的数据底座（Phase A1） |

四 sink 并行写入由 spdlog 内部串行化，业务线程只感知一次格式化成本。

## 2. Qt 版本兼容说明

### 2.1 版本矩阵与实测状态

| Qt \ 编译器 | MSVC | MinGW |
|---|---|---|
| 5.15.2 | ✅ 实测 | ✅ 实测（GCC 8.1） |
| 6.5.3 | ✅ 实测 | ✅ 实测（GCC 11.2） |
| 5.14.2 | 静态风险已清零，运行时验证待环境（用户决定搁置） | 同左 |
| < 5.14 | **编译期 `#error`**（MetaCallParser.cpp），禁止静默降级 | 同左 |

Qt 版本自动探测：根 CMakeLists `find_package(QT NAMES Qt6 Qt5)`，下游统一 `Qt${QT_VERSION_MAJOR}::` 引用，无版本硬编码。

### 2.2 私有头防火墙（核心机制）

MetaCall 解析依赖 `qobject_p.h`（非公开 API）。防护策略：

1. **集中点唯一**：整个工程仅 [MetaCallParser.cpp](../src/event/MetaCallParser.cpp) 允许 include Qt private 头，版本差异注释与 `#error` 兜底全部收敛于此。
2. **路径自带版本号**：Qt6 经 `Qt6::CorePrivate` 传播目标，Qt5 经 `Qt5Core_PRIVATE_INCLUDE_DIRS`（如 `.../include/QtCore/5.15.2/QtCore/private`）——升级 Qt 而未适配时**直接编译失败**，而不是运行期崩溃。
3. **只经 public inline 访问器取值**：`sender()` / `signalId()` 是 qobject_p.h 中的 public inline 函数，仅读值/拷贝指针，不猜成员偏移、不链接任何 Qt 私有符号。
4. **版本门控的公共 API**：跨版本 API 差异用 `#if QT_VERSION` 分流（例：QComboBox 信号 5.15+ 用 `idClicked`，5.14 及以下回退 `buttonClicked`）。

### 2.3 编译器差异实录（MinGW 移植）

| 问题 | 现象 | 解决 |
|---|---|---|
| GCC 8.1 libstdc++ `fs_path.h` bug | `std::filesystem::path::operator!=` 模板推导失败 | 日志目录创建改 `QDir::mkpath`；项目约定：目录操作一律 Qt API |
| K32* API 内联转发缺失 | MinGW 无 K32 前缀导出，链接失败 | `__MINGW32__` 下映射为 psapi 无前缀 API + 链接 `psapi`（CMake 平台条件） |

### 2.4 适配新版本 Qt 的操作清单

1. 编译四矩阵（或至少目标版本）——私有头路径变化会在此暴露；
2. 打开 `MetaCallParser.cpp`，按新版本 qobject_p.h 核实 `QAbstractMetaCallEvent` 访问器（存在性/语义），补版本注释分支；
3. 对照官方 tag 核实 `QMetaObjectPrivate::signal()` 签名（Qt6 曾从 `const QMetaMethodPrivate*` 改为直接 `QMetaMethod`，当前写法两者通用）;
4. 跑 `tests/TestEventWatcher`（含 MetaCall signalId→签名解析断言）。

## 3. MetaCall ABI 适配说明

### 3.1 事实基础（逐版本核实，非假设通用）

`QEvent::MetaCall` 事件的实际类型是 `QAbstractMetaCallEvent`（定义于 qobject_p.h）。三个版本的头文件已逐项核实：

| 版本 | 核实来源 | 结论 |
|---|---|---|
| 5.14.2 | 官方 v5.14.2 tag qobject_p.h L484-506 | 基类与 `sender()`/`signalId()` 访问器存在，结构同 5.15.2 |
| 5.15.2 | 本机源码 qobject_p.h | 同上 |
| 6.5.3 | 本机源码 qobject_p.h L349 | 访问器同名同义；成员声明顺序不同（signalId_ 在前）——本实现只经访问器取值，零偏移假设 |

转型方式与 Qt 源码一致（`QObject::event` 中 `static_cast<QAbstractMetaCallEvent*>`），此处用 `dynamic_cast` 做额外校验，失败安全跳过（PRD 06）。

### 3.2 signalId → 信号签名的规范转换

`QMetaCallEvent` 携带的 signalId 来自 `doActivate` 的 `signal_index = QMetaObjectPrivate::signalOffset(m) + local_signal_index`，**不等于** method index。转回签名必须用：

```cpp
const QMetaMethod signalMethod = QMetaObjectPrivate::signal(senderMo, signalId);
```

实测教训：`method(signalId)` 是错误近似——signalId=3 会被误解析成 `deleteLater()`。Qt 自身（queued_activate / dumpObjectInfo）同款走 `QMetaObjectPrivate::signal`。注意 m 为 nullptr 时该函数 Q_ASSERT 失败（Release 下 UB），必须判空。

### 3.3 sender 生命周期安全（3B 模型）

问题：`QMetaCallEvent::sender()` 是裸指针。queued 投递后、日志时刻之前 sender 可能已析构（槽内自毁、跨线程销毁），日志路径任何 `sender->` 解引用都是 UB；`QPointer` 也无法补救（只能保护注册前就跟踪的对象）。

方案（[MetaCallSenderRegistry](../src/event/MetaCallSenderRegistry.h)）：把身份解析挪到**发射时刻**——此时 sender 正在 emit，必然存活：

- 经 `qt_register_signal_spy_callbacks`（QSignalSpy 同款机制）注册 signal_begin 回调，快照 `{sender 指针值, signalId, metaObject, className, 信号签名, 线程}`；
- 日志路径仅以"指针值 + signalId"查表，**永不解引用 sender**；未命中降级为空字段，绝不猜测；
- 回调内部仅查表与固定缓冲覆写，零动态分配（签名表按 metaObject 首见分配一次）。

### 3.4 进程级互斥与抢占检测

spy 回调是**进程级唯一资源**（Qt 保存指针不拷贝）：QSignalSpy、GammaRay 等注册会覆盖全局回调。处理：

- 仅 `WatchMetaCall` 开启时安装（安装状态以启动配置为准）；
- 每次查询前 `isCallbackActive()` 检测回调指针是否仍归本注册表——被抢占则身份降级为空字段并 WARN 一次，不影响告警主链路。

### 3.5 归属线程精确语义（C1）

- `QThread` 无公开 API 取"某 QThread 对象"的 os id，且发射线程 ≠ 归属线程（跨线程直接 emit）时二者不同；
- [ThreadRegistry](../src/event/ThreadRegistry.h)：发射时刻安全解引用 `sender->thread()`（唯一解引用点），`QThread*` 指针值键注册 + `destroyed` 自动注销（键值生命周期 ⊆ QThread）+ os id 回填 + 64 条上限降级；
- 消费侧归属 id 优先，未观测（0）回退发射线程快照。
