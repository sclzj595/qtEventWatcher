# 27 - V5 实施计划

> 规划定稿：2026-09-29 ｜ 前置状态：V4 全线收官（[docs/26](26_V4终态交付总结.md)）
> 本计划遵循项目既定哲学：分阶段实现、每阶段四矩阵编译 + 冒烟可验证、显式导出不进热路径（PRD 14）、克制配置面

---

## 1. 版本定位与主题

V4 完成工程化与规模化（回归基建 / 分发模型 / 多进程聚合）。终态数据（docs/22 §9）留下两个有数据支撑的收口点：

1. **抑制路径大头被 B2 证伪重定位**：mode=1 实测 10.7µs 中，栈采集仅 ~6µs，其余 ~10µs 在**日志格式化 + RecordSink 结构化采集**——而 fields 的全部消费方（DataExporter / DiagnosticSummarizer / HtmlReporter / UplinkClient）都是冷路径，采集端逐条解析是热路径上的纯浪费；
2. **D 线计数器不可观测**：UplinkClient 的 pushed/dropped/reconnects 只有 C++ 访问器，无外部上报通道（docs/26 §5 已知边界）——跨进程观测健康度缺最后一块。

**V5 主题：热路径收尾与可观测性**——"解析放消费侧"（与 V3 A1"符号解析放导出侧"同一哲学）+ op=health 健康度上行。

## 2. 阶段总览与优先级

| 阶段 | 内容 | 优先级 | 定性 | 依赖 |
|---|---|---|---|---|
| A | 采集链路瘦身（懒解析 + 上行协议 raw 化 + 基准复测） | **P0** | 有实测数据支撑的热路径收口 | 无 |
| B | op=health 健康度上行 | **P1** | D 线已知边界收口，量小 | 无（建议 A 后） |
| C | HTML 聚合段 | 条件触发 | 场景依赖（多进程消费出现时） | — |
| D | Linux 验证 | 条件触发 | 环境依赖 | 环境具备 |

推进建议：A1 → A2 → A3 → B 串行（总量小）；C/D 维持条件触发不入 V5 主线。

## 3. Phase A：采集链路瘦身（P0）

### A1 WatchRecordStore 懒解析（sink 端零解析）

- **现状**：RecordSink::sink_it_ 逐条 parseFields（每条 ~20 次 substr 分配）+ parseFrames + formatTime——风暴期每条告警付费，而消费可能根本不发生（uplink 默认关、导出未开）。
- **任务**：
  1. 环形缓冲只存 `kind/seq/time/raw`（fields/frames 不在 sink 端解析）——顺带降低 4096 条环形内存占用与快照持锁拷贝时长；
  2. 解析后移到 snapshot()/snapshotSince()：**锁外**对返回副本逐条 parseFields + extractQssOp + stack= 拆帧——公共 API 语义不变（返回的 Record 仍含完整 fields/frames，"全量记录"语义保全）；
  3. 解析函数（parseFields/parseFrames/extractQssOp）从 Impl 提升为 WatchRecordStore 公有静态方法——A2 与 aggregator 复用，避免拷贝实现；
  4. formatTime 秒段缓存（sink_it_ 由 sink 互斥串行，秒内只渲染一次）。
- **验收**：TestEventWatcher 既有快照断言逐字段等价（fields/frames 内容与 V4 一致）；四矩阵编译 + 冒烟全绿。
- **风险**：低——行为契约明确（snapshot 出口必然已解析）；白盒消费方全部走 snapshot，无直读环形路径。

### A2 上行协议 raw 化（监控端全链路零解析）

- **任务**：
  1. UplinkClient 线上格式精简：records 只带 `kind/seq/time/raw`（fields/frames 数组不再上行——A1 后监控端本就不再预解析，避免为组包临时解析）；
  2. aggregator 收到 raw 后用 A1 公有静态解析方法重建 fields/frames，存储与 JSON 导出形状不变（host_pid 分组 / records==received 断言口径不受影响）；
  3. dropped 字段语义不变（首批携带 skipped 汇总）。
- **验收**：端到端复跑 V4 D 线双场景——B1 背压（`--stress 20000` 闭环等式不变）+ 断点续推（received==发送总量、seq 无洞）；aggregator 导出 JSON 字段结构与 V4 一致。
- **风险**：中低——协议变更要求监控端与 aggregator 同仓同发（现状即如此，无版本 skew 场景）；协议版本字段不加（克制，内网单工具链）。

### A3 基准复测（docs/22 §10）

- **任务**：busy-user-event-slow 三档复测（Qt5 MSVC，对照 docs/22 §9）：
  - mode=1 风暴抑制路径：10.7µs → 预期 **6~8µs**（诚实预期：fmt 实参替换 2~4µs 是地板，无法在本线消除）；
  - mode=0 完整告警路径：16.8µs → 预期 ~12-13µs；
  - ② 正常路径必须持平（解析后移不触碰正常路径，回归脚本守门）。
- **基线处理**：A 线属**有意改善**，告警场景数字变化会触发漂移检测——复测后 `run_regression.ps1 -UpdateBaselines` 刷新基线并在 docs/22 §10 记录前后对照，不静默。
- **明确不做**：fmt 实参替换成本不动（需绕开 spdlog 格式化改结构化直采，破坏"日志单一数据源"解耦，收益/风险比不成立——B2 同款结论延续）。

## 4. Phase B：op=health 健康度上行（P1）

- **协议**：`{"op":"health","pid":N,"pushed":N,"dropped":N,"reconnects":N,"lastSeq":N}`——复用现有 flushTick 驱动（零定时器：距上次 health 发送 >5s 时随拍附带；constexpr 5s 不入配置面，克制）。
- **任务**：
  1. UplinkClient::flushTick 增加 health 节拍（已连接才发；未连接不发——断线期健康度靠重连后首拍补出）；
  2. aggregator 识别 op=health：per-pid Session 存最新快照 + 退出汇总逐 pid 打印 + JSON 导出 sessions[].health 段；
  3. tail 模式对 reconnects 增量打一行提示（重连事件可视化）。
- **验收**：端到端（--stress + aggregator）断言 health 段存在且 pushed 与记录数自洽；**复用 V4 断点续推场景断言 reconnects≥1**——docs/26 §5"计数器无外部上报通道"边界正式关闭。
- **风险**：低——5s 一行，带宽可忽略；未知 op 在两侧均静默容错（既有协议纪律）。

---

## 5. 依赖关系与推进顺序

```
A1（懒解析）──→ A2（raw 化）──→ A3（基准复测 + 基线刷新）──→ B（health 上行）
```

- A1 是 A2 的前置（解析函数公有化 + 监控端不再持有 fields）；
- A3 必须 A1/A2 落地后跑（数字才反映终态）；
- B 独立于 A，但建议排后（复用 A 线 e2e 场景做验收）。

## 6. 风险清单

| 风险 | 阶段 | 缓解 |
|---|---|---|
| 懒解析破坏"全量记录"语义 | A1 | 解析在 snapshot 出口完成，API 逐字段等价断言；环形内不解析是实现细节 |
| 上行协议变更导致聚合断言口径漂移 | A2 | aggregator 重建 fields 后导出形状不变；复跑 V4 D 线双场景闭环等式 |
| 告警场景数字变化被误判为漂移 | A3 | 有意改善走 -UpdateBaselines + docs/22 §10 前后对照，不静默 |
| health 与 record.push 交错解析 | B | aggregator 按行 op 分发（既有逐行纪律），health 不入 records 计数 |

## 7. 成功标准

1. **默认语义零回归**：snapshot/snapshotSince 返回记录与 V4 逐字段等价（冒烟断言）；②正常路径基线持平；
2. **监控端零解析**：sink 不解析 + 上行不解析——字段解析全部发生在消费侧（导出/聚合），实测降幅入 docs/22 §10；
3. **健康度可观测**：双场景 e2e 中 pushed/dropped/reconnects/lastSeq 跨进程可见，reconnects≥1 断言通过；
4. 每阶段交付即更新 docs/21 §11 实施记录；V5 收官后补 docs/26 式终态总结（或并入 docs/26 追踪补记，视总量定）。
