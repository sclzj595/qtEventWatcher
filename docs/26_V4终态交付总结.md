## 1. 版本定位与完成度

V3 完成了监控能力的纵深（归因到函数级 + SQLite/HTML 出口），V4 转向**工程化与规模化**：让工具从"能接入"升级到"可回归、可分发、可多进程汇聚"——一键回归基建防性能退化，install/find_package 打通 CMake 消费链路，D 线多进程聚合（V3 搁置项 C3 兑现）打通跨进程数据面。

项目版本主线全景：V1 基础事件监控 → V2 数据增值（导出/统计/IPC）→ V3 归因深化（栈/抑制/看门狗）→ **V4 工程化与规模化（回归/分发/多进程）**。

## 2. 各阶段交付明细

### 2.1 A1 一键回归基建

- **scripts/regression/qt-matrix.json**：四矩阵定义（name/buildDir/envPath/exeDir）+ benchmark 配置（quickModes / fullModes / driftTolerance=0.25 / excludeScenarios）；
- **scripts/run_regression.ps1**：逐矩阵 PATH 前置 → 构建 → 冒烟（exit=0 且无 FAIL 行）→ benchmark 解析 → 与 baselines-v3.json 对比关注字段，输出 last-report.md；参数 `-Full/-SkipBuild/-UpdateBaselines/-Strict/-Matrices`；
- **baselines-v3.json**：38 keys × 4 矩阵，键格式 `<matrix>|<mode>|<scenario>|<field>`；
- **漂移检测闭环自证**：alert-first 微样本注入 ±30% 波动 → 触发 DRIFT → excludeScenarios 排除——检测能力本身被验证。

### 2.2 A2 GitHub Actions 回归模板

- windows-latest + aqtinstall，matrix 仅 qt5152-msvc / qt653-msvc（MinGW 工具名随版本漂移，注释模板留用）；
- 步骤：checkout → aqt install-qt（按 Qt Core DLL 反查 QT_ROOT）→ configure → build → smoke → upload-artifact；
- **CI 不跑 benchmark**（runner 噪声不可控）——基线漂移只做本地回归，CI 守编译 + 冒烟。

### 2.3 B1 抑制窗口配置化

- `AlarmSuppressWindowMs`（默认 1000）：env / INI / setter 三通道热更新，sanitizePositive 兜底；
- **签名改造**：AlarmSuppressor::evaluate 去掉全部默认参数强迫显式（两参/三参重载）。教训：字面量 `0` 精确匹配 `int` 重载而非 `int64_t`，默认参数引入重载歧义（冒烟断言失败实证，已写入 AlarmSuppressor.h）；
- EventWatcher / MetaCallWatcher 调用点实时读配置，窗口热更新即时生效；IPC setter 同步。

### 2.4 B2 栈采集时机三档

- `StackCaptureMode`：**0=命中即采（默认，保全量 frames 语义）/ 1=仅窗口首条采（被抑制条免采）/ 2=关闭**，三通道配置；
- **基准复测**（busy-user-event-slow，Qt5 MSVC）：mode=0 16.8µs → mode=1 **10.7µs（-36%）**；
- **诚实洞察**：-36% 低于预期——抑制路径大头是日志格式化 + RecordSink 结构化采集（~10µs），栈采集仅 ~6µs；后续优化应瞄准日志格式化而非栈采集（docs/22 §9 落档）。

### 2.5 C1 config 藏匿

- CusApplication：`WatchConfig` 按值成员 → `std::unique_ptr<WatchConfig>`（析构 out-of-line 满足不完整类型规则，复用 V3 已固化经验）；`watchConfig()` 返回指针透传；`watchEnabled()` 补判空（基类构造/析构期成员未创建/已销毁）；
- src/CMakeLists.txt：config 目录 PUBLIC → PRIVATE，公共面收窄为 **application / logging / qss / include 四目录**；
- **负向审计实证**：benchmark 只构造 CusApplication 不解引用 config——其编译通过即证明 WatchConfig.h 不再经公共头传播（否则 PRIVATE 对其不可见直接报错）。

### 2.6 C2 install / find_package 分发模型

- **install 三件套**：install(TARGETS ... EXPORT) + install(EXPORT NAMESPACE QtEventWatcher::) + configure_package_config_file + write_basic_package_version_file（SameMajorVersion）；
- **公共面头扁平安装**到 `<prefix>/include` 根（与构建态扁平 include 一致）；spdlog 随包自装（SPDLOG_INSTALL=ON + `find_dependency(spdlog CONFIG)`）；Qt 依赖按 `@QT_VERSION_MAJOR@` 配置期展开；
- **consume-test 双模型验收**（独立 CMake 工程防递归）：模式 1 find_package（CMAKE_PREFIX_PATH）/ 模式 2 add_subdirectory（QEW_ROOT + 关闭 tests/examples + ALIAS 统一命名空间）——**四矩阵 × 双模型 = 8/8 PASS**；
- **踩坑五则**（均已修复留档）：① `add_subdirectory(... EXCLUDE_FROM_ALL)` 把子目录从顶层 install 序列剔除；② `install(EXPORT)` 硬校验 INTERFACE 属性禁源码树绝对路径（Ninja/MinGW 报错，MSVC 竟不报）→ `$<BUILD_INTERFACE:>` 包装；③ `CMAKE_SOURCE_DIR` 在 add_subdirectory 接入模式指向消费工程 → 用 `PROJECT_SOURCE_DIR`；④ 公共头必须扁平安装到 include 根；⑤ `cmake --install` 不触发 reconfigure，改 install 规则后须先 build。

### 2.7 D1 上行链路 UplinkClient

- **关键设计转向**：docs/25 原设想"独立有界队列 + 专线上下文"，实现改为**差量游标拉取**——数据本体留在 WatchRecordStore 环形缓冲（4096 即有界队列），客户端只持 seq 游标（`snapshotSince` 二分定位差量段）。**热路径增量为 0**（优于 ≤+50ns 验收线），断线时"游标不前进"即天然积压，免去第二条解析管道；
- **UplinkClient**（非 QObject 组合式）：主线程 QTimer 周期驱动（默认 200ms），NDJSON `op=record.push` 批量推送（≤64 条/行且 ≤8KB，首批携带 skipped 汇总）；断线重连内置状态机（指数退避 100ms 倍增至 5s，静默无告警噪音）；名字/周期每拍实时读（IPC 热更新即时生效，空名断开闲置）；
- **配置三通道**：`QT_EVENT_WATCHER_UPLINK_NAME`（空 = 关闭，**默认关 = 零回归保证**）+ `QT_EVENT_WATCHER_UPLINK_FLUSH_MS`，env / INI / setter / IPC 全通道。

### 2.8 D2 aggregator 中心收集器

- **examples/aggregator**（console）：QLocalServer 多连接 + NDJSON canReadLine 帧界（与 IpcConfigServer 同构反向复用）+ 按 pid 分组聚合（每 pid 4096 环形，超限丢最旧 + dropped 累计）+ `--tail` 实时流 + `--duration` 定时退出 + `--out` 按 host_pid 分组 JSON 导出；
- **端到端验收**：aggregator + 2×basic_demo（不同 pid）→ sessions=2 / received=120 / dropped=0 / records==received 断言全过。

### 2.9 D3 聚合报告（诚实降级）

- 已落地：aggregator host_pid 分组 JSON 导出（多进程段数据模型）+ tail 实时流；
- **降级决策**：docs/25 设想的"HtmlReporter 扩展多进程段"未做——HtmlReporter 签名绑定单例（WatchRecordStore::instance + EventStatistics），与跨进程聚合数据模型不匹配；为尚无真实用户的场景重构导出接口，收益低于成本。HTML 聚合段留待场景明确后追加。

### 2.10 D 线遗留缺口补测（背压与断点续推）

basic_demo 新增 `--stress <count>` 风暴源（50ms 节拍合成 DEBUG 级慢事件告警——RecordSink 在 WatchLogger::initialize 时无条件挂接、与监控位无关，文件/控制台 sink 用户级不刷屏）：

- **背压覆盖**（demo `--stress 20000` 先行 12s 后拉起 aggregator）：`upstream dropped=5952` + `received=14048 dropped=15904 records=4096`——**闭环等式 `20000 = 5952(上游环形覆盖) + 14048(送达)`**，且 `15904 = 5952(对端 skipped) + 9952(Session 溢出 14048-4096)`；留存 seq=[15905..20000] 与 skipped 精确自洽；
- **断点续推**（aggregator 存活 2s 下线 → demo 断线积压 ~2.5s → 同名重启）：`received=6000` **精确等于发送总量，零丢失零 skipped**（重连路径行为级实证——计数器无外部上报通道）；留存 seq=[1905..6000] gaps=0，头部 1904 条精确等于 Session 溢出弹出数。

## 4. 工程质量资产

- **回归纪律升级**：从"每阶段手工四矩阵编译+冒烟"升级为**脚本化一键回归 + 基线漂移检测**——性能退化在合入前被脚本拦截，不再依赖人眼比对 docs/22 表格。
- **V4 新增踩坑知识库**（已固化项目记忆，择要）：
  - AlarmSuppressor::evaluate 去默认参数强迫显式——字面量 `0` 精确匹配 int 重载，默认参数引入重载歧义；
  - install/export 五则（EXCLUDE_FROM_ALL 剔除 install 序列 / BUILD_INTERFACE 包装 / PROJECT_SOURCE_DIR / 扁平安装 / install 不触发 reconfigure）；
  - `CMAKE_SOURCE_DIR` 在 add_subdirectory 接入模式指向消费工程——依赖路径解析必须用 `PROJECT_SOURCE_DIR`；
  - 三矩阵并发构建竞争失败（"Generate step failed"）——四矩阵必须串行；
  - PowerShell 管道 `Select-Object -First N` 会截断上游原生命令（cmake install exit -1）；
  - MinGW6 冒烟 0xC0000135 = PATH 段未随矩阵切换——逐矩阵 PATH 前置必须严格跟随；
  - RecordSink 在 WatchLogger::initialize 时无条件挂接（与监控位无关）——合成日志即可驱动上行链路验收，无需真实卡顿。
- **设计决策范式**："独立有界队列"→"环形缓冲 + 差量游标"——复用既有存储即天然有界，热路径零增量；降级决策（D3 HTML 段）以"无真实用户不重构接口"为由诚实落档。

> 本节为简版兑现映射；V5 完整终态总结见 [docs/28](28_V5终态交付总结.md)。

### 6.1 A 线：采集链路瘦身（候选 1）

- **A1 懒解析**：RecordSink::sink_it_ 零解析——环形缓冲只存 kind/seq/time/raw，字段/栈帧解析后移到 snapshot/snapshotSince 出口锁外 hydrate；hydrateRecord / parseFields / parseFrames 转公有静态（解析逻辑单点化，aggregator 消费侧复用同一实现）；formatTime 秒段缓存（localtime_s 为该函数大头，同秒只渲染一次 HH:mm:ss；RecordSink 为 base_sink\<std::mutex\>，sink_it_ 天然串行，普通 static 无竞态）。
- **A2 raw 化**：UplinkClient 组包删 fields/frames 序列化，线上仅 kind/seq/time/raw；aggregator rebuildStructured 以 hydrateRecord 消费侧重建，导出形状与 V4 逐字段一致。A2 验收复跑 V4 D 线双场景全过：背压闭环 `20000 = 5568(上游环形覆盖) + 14432(送达)` + fields 重建 12 字段；Stop-Process 强杀重连 `received=6000` 精确、gaps=0（比 V4 的优雅退出更严格）。
- **A3 诚实落档**（[docs/22](22_性能基准报告.md) §10）：mode1 9.3~9.5µs（**-12%**）低于预期 6~8µs——移除的 parseFields 实测仅 ~1.3µs，现代 allocator 下 ~20 次 substr 小分配远比规划估算（2~4µs）便宜。真实收益是架构性的：①风暴期无消费则零解析成本，消费时缩短快照持锁时长；②环形 4096 条不再存 fields/frames 容器，内存占用降低；③解析单点化。方法论教训：告警路径 benchmark 必须多轮取中位数，单次摆动不可信（首跑 20.7µs 为冷启动噪声，qt653 单次 17.3→25.5µs 跨基线两侧）。`busy-user-event-alert` 按 alert-first 先例移入 excludeScenarios（噪声态单次摆动 12~25µs 即 ±40% 跨容差带），③ 告警路径数字改由 docs/22 逐版本多轮复测守门。

### 6.2 B 线：健康度上行（候选 2）+ 计划外修复

- **op=health**：随 flushTick 5s 节拍（零定时器，healthClock 随拍），已连接才发，payload = pid / pushed / dropped / reconnects / lastSeq；aggregator per-pid 保存最新 health（tail 增量行 + 退出汇总 + --out JSON `health` 段）。
- **计划外发现与修复**：health 让 reconnects 计数器首次可读，暴露原实现缺陷——只在 socketFailed（写后 error）置位后才计数，而对端进程被杀时本地无写错误可观察（socketFailed 恒 false），计数恒 0。修复：`connected / everConnected` 双标志，断线检测统一入口改为连接态变化（见 UnconnectedState 置 false；再次建连且 everConnected 时计数），同时覆盖"写后 error"路径。
- **验收**（Stop-Process 强杀 aggregator → demo 重连 → 同名重启）：`health{pushed=6000 dropped=0 reconnects=1 lastSeq=6000}`，与 received 精确自洽。

### 6.3 验证与遗留

- 四矩阵 build + smoke 全绿；最终 quick 回归 4/4 PASS 无 DRIFT（uplink/health 默认关闭 = 热路径零增量）。
- 逐 Phase 实施记录见 [docs/21](21_版本规划与交付物.md) §11，基准复测见 docs/22 §10。
- 遗留：HTML 聚合段 / Linux 验证维持条件触发；本篇 §5 已知边界两项（计数器无外部上报通道、重连计数非直读）均已由 B 线关闭。
