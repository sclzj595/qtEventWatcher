## 1. 版本定位与完成度

V4 完成工程化与规模化后，终态数据（docs/22 §9）留下两个有数据支撑的收口点：①抑制路径大头被 B2 证伪重定位——fields 的全部消费方（DataExporter / DiagnosticSummarizer / HtmlReporter / UplinkClient）都在冷路径，采集端逐条解析是热路径上的纯浪费；②D 线计数器（pushed/dropped/reconnects）无外部上报通道，跨进程健康度不可观测。

V5 主题：**热路径收尾与可观测性**——"解析放消费侧"（与 V3 A1"符号解析放导出侧"同一哲学）+ op=health 健康度上行。

项目版本主线全景：V1 基础事件监控 → V2 数据增值 → V3 归因深化 → V4 工程化与规模化 → **V5 热路径收尾与可观测性**。

| 阶段 | 内容 | 状态 |
|---|---|---|
| A1 | WatchRecordStore 懒解析（sink 零解析 + 快照出口 hydrate） | ✅ 完成 |
| A2 | 上行协议 raw 化 + aggregator 消费侧重建 | ✅ 完成 |

**验证基线**：四矩阵（Qt 5.15.2 / 6.5.3 × MSVC 2019 / MinGW GCC 8.1·11.2）全程编译 + 冒烟纪律不变；最终 quick 回归 **4/4 PASS 无 DRIFT**（uplink / health 默认关闭 = 热路径零增量）；A2 双场景 e2e 闭环等式与 B 线强杀验收全过。

## 2. 各阶段交付明细

### 2.1 A1 WatchRecordStore 懒解析

- **sink 端零解析**：RecordSink::sink_it_ 移除 parseFields（每条 ~20 次 substr 分配）/ parseFrames / QSS op 提取，环形缓冲只存 `kind/seq/time/raw`——风暴期无消费则零解析成本；顺带降低 4096 条环形内存占用与快照持锁拷贝时长；
- **快照出口 hydrate**：snapshot()/snapshotSince() 锁外对返回副本逐条重建 fields/frames（顺序与 V4 采集端逐条等价：QSS op 提取 → parseFields → stack= 拆帧）——公共 API 语义不变，"全量记录"语义保全；
- **解析单点化**：hydrateRecord / parseFields / parseFrames 提升为 WatchRecordStore 公有静态方法（extractQssOp 经 hydrateRecord 内化）——A2 与 aggregator 消费侧复用免拷贝实现；
- **formatTime 秒段缓存**：localtime_s 是该函数大头（内核级时区换算），同秒只渲染一次 HH:mm:ss；RecordSink 为 base_sink\<std::mutex\>，sink_it_ 天然串行，普通 static 无竞态；
- 验证：四矩阵编译 + 冒烟全绿；DiagnosticSummarizer / DataExporter 的 fields 消费断言即逐字段等价的行为级验证。

### 2.2 A2 上行协议 raw 化（监控端全链路零解析）

- UplinkClient 线上格式精简：records 只带 `kind/seq/time/raw`（A1 后监控端本就无 fields 可序列化，组包不再临时 hydrate）；
- aggregator 增 rebuildStructured()：用 WatchRecordStore::hydrateRecord 消费侧重建，存储与 JSON 导出形状与 V4 逐字段一致（fields=[[k,v]..] / frames=[[mod,off]..]）；
- **双场景验收复跑**（V4 D 线同款）：
  - 背压 `--stress 20000` → upstream dropped=5568 + received=14432，**闭环 `20000 = 5568(上游环形覆盖) + 14432(送达)`**，dropped=15904 = 5568 对端 skipped + 10336 Session 溢出；导出 fields 重建 12 字段正确；
  - 断点续推（aggregator 存活 2s 时 **Stop-Process 强杀**——真实进程死亡，比 V4 的优雅退出更严格）→ received=6000 精确等于发送总量、seq gaps=0；
- 协议版本字段不加（监控端与 aggregator 同仓同发，无版本 skew 场景）。

### 2.3 A3 基准复测（诚实落档 docs/22 §10）

- **收益低于规划预期**：mode=1 风暴抑制路径 10.7 → **9.3~9.5µs（-12%，-1.3µs）**（预期 6~8µs）。诚实归因：sink 端 parseFields/parseFrames 实际成本仅 ~1.3µs——现代 allocator 下 ~20 次 substr 小分配远比按 2~4µs 的估算便宜；剩余 ~9.4µs 地板 = fmt 实参替换（12 实参）+ payload 拷贝 + formatTime + 4 sink 分发 + 环形入队；
- mode=0 15.1~16.6µs 持平（首跑 20.7µs 为冷启动噪声）；mode=2 10.3µs 与 mode=1 同级；②正常路径 687~790ns 持平（V4 610~952 区间内）；
- **V5 A 线的真实收益是架构性的**：①监控端全链路零字段解析（风暴期无消费则零解析，消费时缩短快照持锁时长）；②环形 4096 条不再存 fields/frames 容器；③解析逻辑单点化。-1.3µs 是搭车收益；
- **基线与容差**：`-UpdateBaselines` 刷新 23 keys × 4 矩阵；`busy-user-event-alert` 按 alert-first 先例移入 excludeScenarios——噪声态单次摆动实测 12~25µs（±40%）跨容差带（qt653 复跑 17.2/19.1/22.7µs 跨基线两侧即证）；③告警路径数字改由 docs/22 逐版本多轮复测守门。排除后回归 4/4 PASS 无告警噪声。

### 2.4 B op=health 健康度上行（含计划外修复）

- **协议**：`{"op":"health","pid","pushed","dropped","reconnects","lastSeq"}`——flushTick 内 5s 节拍随拍附带（零定时器，kHealthIntervalMs constexpr 不入配置面）；已连接才发，断线期不发、重连后首个到期拍补出；
- aggregator：Session 存最新健康度快照（不入 records 计数）+ tail 模式 reconnects 增量打行（重连事件可视化）+ 退出汇总 health{...} + JSON 导出 sessions[].health 段；
- **计划外发现与修复**：health 让 reconnects 计数器首次可读，暴露原实现缺陷——`++reconnects` 只在 socketFailed（写后 error）置位后触发，而对端进程被杀时本地无写错误可观察（下一拍直接见 UnconnectedState），计数恒 0。修复：断线检测统一入口化（connected / everConnected 双标志，Unconnected/Connecting 分支置 false），**建立过连接后再次建连即计**，同时覆盖"对端退出"与"写后 error"两种断线路径；
- **验收**（强杀 aggregator → demo 重连 → 同名重启）：`health{pushed=6000 dropped=0 reconnects=1 lastSeq=6000}` 与 received=6000 全自洽——docs/26 §5"计数器无外部上报通道 / 重连计数非直读"两条已知边界正式关闭。

## 4. 工程质量资产

- **设计哲学延续**："解析放消费侧"与 V3 A1"符号解析放导出侧"同源——热路径只存原始数据，解析成本由冷路径消费方付费。两次实践均验证：热路径上的"预加工"若消费方全在冷路径，就是纯浪费。
- **方法论校准**（均已固化项目记忆）：
  - 告警路径 benchmark 必须多轮取中位数，单次摆动不可信——首跑 20.7µs 冷启动噪声、qt653 单次 17.3→25.5µs 跨基线两侧，均会被误判为回归/改善；
  - 微分配成本直觉偏差：~20 次 substr 小分配在现代 allocator 下仅 ~1.3µs——规划收益估算（2~4µs）偏高近 2 倍。后续优化立项前先测真实成本结构，再定预期。
- **可观测性红利**：op=health 让 reconnects 计数器首次可读，立刻暴露隐藏缺陷（对端被杀时计数恒 0）——"给计数器接上出口"本身就是最好的缺陷测试。
- **excludeScenarios 扩容原则**：噪声态场景（单次摆动 ±40% 实测）按 alert-first 先例移入排除，数字由 docs/22 逐版本多轮复测守门；DRIFT 本为提示级（-Strict 才阻断），回归脚本保留对稳定场景的拦截能力。

**已知边界**：
- 抑制路径 ~9.4µs 地板中，fmt 实参替换为最大可压缩项——但需绕开 spdlog 格式化改结构化直采，破坏"日志单一数据源"解耦，收益/风险比不成立（docs/27 A3"明确不做"），除非真实诉求出现；
- reconnects / dropped 计数器已具备上行通道（op=health），边界关闭；aggregator 侧 dropped（Session 溢出）仍在 JSON 导出与 tail 行可见，无独立告警通道（内网单工具链，克制）。

**V6 方向候选**：无主动立项项——既有候选仅剩条件触发（Linux 验证）。若需再压抑制路径，先复测 ~9.4µs 地板的成本结构再立项。
