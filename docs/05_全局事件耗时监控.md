# Qt 卡顿排查辅助器 PRD 05：全局事件耗时监控

## 1. 实现方式
继承 `QGuiApplication`，重写 `notify(QObject *receiver, QEvent *event)`，在事件进入和退出时进行计时。

## 2. 采集字段
- QEvent 类型编号。
- 可解析的事件名称。
- 实际耗时（Inclusive）与自身耗时（Exclusive，见 §6）。
- 嵌套深度 nestingDepth（见 §6）。
- Receiver 类名。
- Receiver objectName。
- 线程快照：当前线程 ID、Receiver 线程 ID（见 §7）。
- 时间戳。

## 3. 阈值
默认慢事件阈值建议为 30ms，必须支持配置。

建议：
- 16ms：关注掉帧风险。
- 30ms：默认 UI 卡顿告警。
- 100ms：严重阻塞。
- 500ms：明显冻结。

## 4. 性能要求
当功能关闭时快速返回；正常事件不产生日志；仅在启用监控且达到阈值时执行完整异常处理。

## 5. 异常处理
notify 必须保证监控代码自身异常不会影响业务事件分发。

## 6. 嵌套事件（notify 重入）采集策略（定稿）
`QApplication::notify()` 不保证线性调用：事件处理中调用 `processEvents()` 或某些 Qt API 内部触发再分发时，会形成 notify 嵌套，父事件耗时包含子事件耗时，直接相加会产生重复计费。

采用 **Inclusive / Exclusive 双耗时模型**：

| 指标 | 定义 | 回答的问题 |
|---|---|---|
| Inclusive Cost（elapsedNs） | 进入到离开当前 notify() 的完整墙钟耗时 | 这个事件的整个处理链路花了多久 |
| Exclusive Cost（exclusiveElapsedNs） | 扣除嵌套 notify 子事件耗时后的自身耗时 | 真正消耗时间的是哪个事件自己的逻辑 |

示例：A=120ms（内含 B=80ms，B 内含 C=20ms）→ A_exclusive=40ms、B_exclusive=60ms、C_exclusive=20ms。

- `WatchEventInfo` 增加字段：`nestingDepth`（最外层=0，每层重入 +1）、`elapsedNs`、`exclusiveElapsedNs`；提供 `elapsedMs()` / `exclusiveElapsedMs()` 便捷转换。
- 慢事件判断**默认基于 Inclusive Cost**（用户首先需要知道哪个事件的完整链路造成卡顿）。
- 慢事件日志附带嵌套信息：`depth=0 event=MouseMove costMs=120.3 exclusiveCostMs=40.1`。
- 嵌套事件不得被错误地重复计数为多个独立主线程执行阶段。
- 诊断 UI 可同时展示两种耗时。

## 7. 线程信息采集（定稿）
- 普通 Event 至少记录：当前线程 ID（`QThread::currentThreadId()`）与 Receiver 线程 ID（`receiver->thread()`）。
- 内部统一保存整数快照（`quintptr`），不长期持有 `QThread*`。
- 正常情况下 CurrentThread == ReceiverThread；不一致本身即有诊断价值。
