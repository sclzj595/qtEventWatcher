# Qt 卡顿排查辅助器 PRD 19：UI / UX 与交互设计规范

## 1. 产品定位
现代桌面开发工具 + 性能诊断软件。目标气质：现代 IDE + 系统诊断工具 + 轻量性能分析器。
明确不做：老式 Windows 控制面板、工业监控台、深色监控大屏、全屏仪表盘。

## 2. 核心原则
- 功能优先但不牺牲美观；用户 3 秒内得到答案：有无异常 / 什么异常 / 严重程度 / 发生在哪。
- 不为"专业感"堆砌仪表盘、百分比、圆环、巨大数字、无意义图表、满屏状态灯。
- 低视觉噪声 + 高有效信息密度：视觉简洁 ≠ 信息极少；表格可以密集，但行高统一、字体清晰、重点突出、少边框。

## 3. 布局

```text
┌──────────────────────────────────────────────────────┐
│ QtEventWatcher                         ● 监控中      │
├──────────────┬───────────────────────────────────────┤
│  概览        │  监控概览                             │
│  慢事件      │  [KPI 卡片行]                         │
│  MetaCall    │  最近异常                             │
│  高频事件    │  ...                                  │
│  QSS         │                                       │
│  运行环境    │                                       │
│  测试场景    │                                       │
└──────────────┴───────────────────────────────────────┘
```

左侧轻量导航 + 右侧内容区 + 清晰页面标题 + 卡片式信息组织 + 少量分割线 + 合理留白。

## 4. 视觉禁令
1. **过度深色**：禁止纯黑 + 大量深灰框 + 荧光绿/红/黄的工业监控风。Dark 主题允许，但必须按 Background → Surface → Elevated Surface 亮度分层。
2. **满屏边框**：层级用背景层次 / 间距 / 字体 / 卡片 / 轻微边界建立，不是每个元素画矩形框。
3. **过度告警色**：强调色只用于状态 / 数值 / 图标的少量强调。语义约定：正常=中性、信息=蓝、注意=Amber、异常=Red；不整页染红。
4. **不依赖复杂图表制造专业感**。

## 5. 视觉体系

### 5.1 色彩令牌
Primary / Accent / Success / Warning / Error / Info / Background / Surface / Border / Text / Secondary Text。
各功能模块（慢事件 / MetaCall / Statistics / QSS）统一用 Primary，异常才用 Warning / Error；不每个模块一个主题色。

### 5.2 字体
- Windows 优先 Segoe UI，中文 Microsoft YaHei，Qt 默认字体 fallback。
- 层级：Page Title / Section Title / Body / Secondary / Caption；不过多字号。

### 5.3 间距
统一 spacing system：4 / 8 / 12 / 16 / 24 / 32 px。
常用：页面边距 24、卡片间距 16、卡片内部 16、控件间距 8~12、标题与内容 8；避免控件紧贴。

### 5.4 圆角
Card 10~12 / Button 8 / Input 8 / Badge 6；禁止巨大圆角与全面胶囊化，仅状态标签、筛选标签适合 Pill。

## 6. 按钮层级

| 层级 | 用途 |
|---|---|
| Primary | 最重要的操作：开始监控 / 导出报告 / 刷新依赖 |
| Secondary | 刷新 / 清空 / 查看详情 |
| Tertiary | 更多 / 设置 / 筛选 |
| Danger | 仅不可逆操作：清除全部数据 / 停止关键操作 |

不让每个按钮都有强烈视觉重量。

## 7. 交互规则
- 顶栏全局状态始终可见：`● 监控中` / `○ 已停止`；点击直接启停，不进设置页。
- 概览为默认首页。
- 无异常显示 `✓ 暂无异常`，而不是四个 0；有异常条目含类型、对象链路、耗时、相对时间（如 `⚠ 慢事件 / MouseMove → MainWindow / 87.4 ms / 刚刚`）。
- 详情交互：单击 → 详情（侧边抽屉 / Dialog，不跳页）；双击 → 详细信息；右键 → 复制 / 导出 / 筛选。详情字段示例见 PRD 17 §3.2。
- 表格：重点信息（耗时数值）突出、单位必须明确、行高统一、少边框。
- 高频事件必须同时给：次数/周期 + 总耗时（如 `MouseMove 155 次/1 秒，总耗时 83.2 ms`），让用户判断高频是否真的消耗主线程。
- 轻量操作用 Toast（`✓ 配置已更新`），不用频繁弹窗；仅不可逆操作弹确认（如"清空所有诊断记录？"）。
- 核心操作一步完成：开始/停止监控、刷新环境、查看异常、导出报告；禁止多层菜单跳转。
- 快捷键：Ctrl+R 刷新；Ctrl+Shift+R 启停监控；Ctrl+E 导出报告；Ctrl+L 聚焦日志（以页面操作不冲突为准）。

## 8. 状态完整性
所有页面必须完整处理三态，不允许空白页：
- Loading：`正在读取运行环境...`
- Empty：`暂无诊断数据`
- Error：`无法读取模块信息 [重试]`

## 9. 主题与可访问性
- Light / Dark 双主题，默认跟随系统；设置 → 外观切换。
- Light：浅灰背景 + 白 Surface + 深灰文字 + 中灰 Secondary + 低对比 Border；不用纯白+纯黑刺眼组合。
- 对比度达标；状态不只靠颜色（🔴 必须配文字）；hover / pressed / 键盘焦点状态明确；最小点击区域合理。

## 10. 运行环境与依赖树 UI
- 运行环境按分组表格呈现（Application / Qt / Compiler / 运行模块），不是"工程师黑框"；支持复制路径、打开目录、刷新、查看依赖。
- 依赖树用现代 TreeView（数据见 PRD 16 §6）；缺失项点击展开搜索位置与可能原因。

## 11. 技术约束
- Qt Widgets：QWidget / Qt Layout / Model-View / QTableView / QTreeView / QStackedWidget；QSS 只做主题与视觉。
- 不引入 QML / Qt Quick / WebView / Electron / 第三方 Web UI。
- Core 与 UI 解耦：`QtEventWatcherCore ← Basic Demo UI` 单向依赖；Core 不出现任何 UI 类型。
- 响应式：至少适配 1024×768 / 1280×720 / 1440×900 / 1920×1080；缩放后内容自适应、表格可伸缩、长文本不溢出、导航不挤压内容。

## 12. 验收清单
- [ ] Light / Dark 双主题
- [ ] 默认首页为概览，左侧导航清晰
- [ ] 全局监控状态始终可见
- [ ] 无异常明确显示"暂无异常"
- [ ] 异常一键查看详情（Event / MetaCall / Statistics / QSS 分区明确）
- [ ] Runtime Environment 独立页面；DLL / Plugin / Dependency Tree 可查看
- [ ] Test Scenario 与正式诊断视觉隔离
- [ ] 无工业风边框、无满屏高饱和告警色、不靠复杂图表撑专业感
- [ ] 支持窗口缩放，操作路径一步完成
- [ ] Loading / Empty / Error 状态完整
- [ ] Core 与 UI 完全解耦；不引入 QML / Qt Quick
